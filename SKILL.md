# Правила оформлення звітів у Typst (ДСТУ ХНУРЕ)

Цей скілл призначений для створення академічних звітів у форматі Typst з використанням шаблону ХНУРЕ (`@local/nure:0.1.1`) та дотримання стандартів ДСТУ.

## Структура скілла та додаткові матеріали

Усередині цього скілла містяться важливі файли. Якщо вам (агенту) потрібні деталі реалізації, обов'язково прочитайте їх (Read / view_file / cat):

- `resources/README.md` — офіційна документація пакета `nure`, скопійована з
  першоджерела. Містить: перелік шаблонів (`pz-lb` для практичних і
  лабораторних, `coursework` і новіший `coursework-v2` для курсових); утиліти
  (`nheading` — ненумеровані заголовки, `hfill` — заповнення рядка,
  `uline` — підкреслені поля для заповнення, `bold`, `img`); спосіб винести
  метадані в окремий `doc.toml` замість переліку аргументів у коді; формат
  бібліографії `bibl.yml` та підтримувані типи джерел; рекомендовану структуру
  проєкту. Це основне джерело, коли треба дізнатися, який аргумент як
  називається.
- `resources/lab.typ` — готовий кістяк лабораторної роботи з першоджерела:
  виклик `pz-lb` із заповненими полями, типові розділи (мета, хід роботи,
  висновки, контрольні запитання) і приклад додатків. Зручно копіювати як
  стартову точку нового звіту; замість тексту там `#lorem(...)`.
- `resources/utils.typ` — невеликий помічник `img(path, caption)`, який робить
  `#figure` із зображенням і сам виводить мітку для посилань із шляху до файлу.
  Його копіюють у корінь проєкту, щоб шляхи до картинок рахувалися відносно
  проєкту, а не кореня пакета.
- `examples/example-lb.typ` — еталонний приклад реального звіту. Використовуйте його як зразок для оформлення великих робіт, додатків та лістингів коду.

## Першоджерело пакета

Оригінальний Typst-пакет `nure` живе тут:
https://github.com/linerds/typst_nure_template/tree/0.1.1/template/default
(дзеркало Gitea: https://gitea.linerds.us/pencelheimer/typst_nure_template).

Файли в `resources/` — це лише знімок, зроблений із цього репозиторію, і він
може відставати. Тому деталі API (сигнатури `pz-lb`, `coursework`,
`coursework-v2`, повний перелік аргументів, утиліти, змінні стилю) та свіжі
приклади використання спершу уточнюйте в самому репозиторії, а вже потім
покладайтеся на цей знімок.

Найнадійніше джерело — встановлений локальний пакет, бо саме його компілює
Typst. Дивіться `~/.local/share/typst/packages/local/nure/0.1.1/`: файл
`src/lib.typ` містить усі публічні шаблони з doc-коментарями над кожним
аргументом, а `template/default/` — готові приклади. Якщо пакет встановлено як
git-клон, перевірити наявність оновлень можна через `git -C <шлях> status -sb`.

Увага: розділ про встановлення під Windows в README першоджерела наводить
приклад із функцією `nure-report` та аргументами `discipline`/`author`/
`supervisor` — такої функції та таких аргументів у пакеті немає. Користуйтеся
`pz-lb` з `authors:`/`mentors:`/`subject:`, як описано нижче.


## 1. Ініціалізація та налаштування документа

Для ПЗ та ЛБ використовується шаблон `pz-lb`. Усі аргументи мають формат `kebab-case`.

```typst
#import "@local/nure:0.1.1": pz-lb, style.appendices, style.spacing

#show: pz-lb.with(
  title: "Назва роботи",
  subject: "АПЗ",
  layout: "ХНУРЕ",
  type: "ПЗ", // або "ЛБ"
  number: 2,
  edu-program: "ПЗПІ",
  university: "ХНУРЕ",
  mentors: (
    (name: "Петренко П. П.", degree: "ст. викладач кафедри ПІ", gender: "m"), // m - чоловік, f - жінка
  ),
  authors: (
    (name: "Іваненко І. І.", edu-program: "ПЗПІ", group: "XX-X", gender: "m", variant: none),
  ),
)
```

## 2. Стилістика тексту та граматика (Безособовий стиль)

В академічних звітах суворо заборонено використовувати першу особу ("я зробив", "ми дослідили"). Текст має бути написаний у безособовій формі або пасивному стані:

- **Неправильно:** Я відкрив вікно та виділив задачі.
- **Правильно:** Було відкрито вікно та виділено задачі.
- **Неправильно:** Під час роботи я навчився створювати зв'язки.
- **Правильно:** Під час виконання роботи було отримано навички створення зв'язків (або "було розглянуто як створювати зв'язки").

Також уникайте надлишкового форматування (наприклад, жирного тексту `*жирний*`), якщо цього не вимагає структура документа.

## 3. Списки та пунктуація

Списки мають суворо відповідати правилам оформлення:

1. Речення перед списком закінчується двокрапкою (`:`).
2. Перша літера після двокрапки (в тому числі на початку кожного елемента списку) має бути **малою** (за винятком абревіатур чи власних назв типу `Google`, `Start-to-Finish`).
3. Між елементами списку ставиться крапка з комою (`;`).
4. Після останнього елемента ставиться крапка (`.`).

**Приклад:**

```typst
Для гнучкого планування було застосовано типи зв'язків:
- затримка (Delay): встановлена між задачами;
- випередження (Lead): дозволяє розпочати реалізацію раніше;
- інші типи зв'язків: використовуються за потреби.
```

## 4. Заголовки та інтервали

- **Не пишіть цифри в заголовках вручну!** Шаблон Typst автоматично генерує нумерацію для заголовків 1-го (`=`), 2-го (`==`) та 3-го (`===`) рівнів.
  - **Неправильно:** `=== 1. Формування послідовностей`
  - **Правильно:** `=== Формування послідовностей`
- Використовуйте змінну `spacing` (імпортовану з пакета) для усунення зайвих відступів перед текстом після заголовку: `#v(-spacing)`

## 5. Робота із зображеннями (Скріншоти)

Для вставки зображень стандартним методом використовуйте блок `#figure`:

```typst
#figure(
  image("img/project.png"),
  caption: "Скріншот вікна задач проєкту зі встановленими зв'язками",
)
```

### Плейсхолдер, коли зображення ще немає

Якщо за змістом потрібен рисунок, але самого файлу зображення немає (скріншот
ще не зроблено, користувач не надав його), НЕ пропускайте рисунок і НЕ
вигадуйте шлях до неіснуючого файлу — вставте плейсхолдер: світло-сірий
прямокутник, усередині якого той самий текст, що й у підписі знизу.

Оголосіть помічник один раз після налаштування документа:

```typst
#let placeholder(caption, height: 6cm) = figure(
  rect(
    width: 100%,
    height: height,
    fill: luma(230),
    stroke: 0.5pt + luma(170),
    inset: 1em,
  )[
    #set align(center + horizon)
    #text(fill: luma(90), caption)
  ],
  caption: caption,
)
```

Далі використовуйте його замість `#figure(image(...))`:

```typst
#placeholder("Скріншот вікна задач проєкту зі встановленими зв'язками")
#placeholder("Діаграма компонентів системи", height: 8cm)
```

Нумерація («Рисунок 1.1 – ...») та посилання працюють так само, як для
звичайного `#figure`. Коли з'явиться справжній файл, достатньо замінити виклик
`placeholder(...)` на `#figure(image(...), caption: ...)` з тим самим підписом.

Обов'язково повідомте користувачеві перелік плейсхолдерів, які було вставлено,
щоб він знав, які скріншоти треба доробити перед здачею.

## 6. Оформлення додатків (Appendices)

Усі додатки (програмний код, результати роботи, скріншоти презентації, посилання на відео) мають йти в кінці документа.
Перед першим додатком ОБОВ'ЯЗКОВО використовується правило `#show: style.appendices` (або `appendices`), яке змінює формат заголовків на "Додаток А", "Додаток Б" тощо. Усі заголовки додатків позначаються одним знаком `=`.

**Приклад оформлення розділу додатків:**

```typst
#show: style.appendices

= Відеозапис
Відеозапис презентації: https://youtu.be/...
Хронологічний опис:
00:00 Вступ
01:30 Основна частина

= Слайди презентації
#for i in range(8) {
  figure(image("prez.pdf", page: i + 1), caption: "Слайд " + str(i + 1))
}
```

## 7. Програмний код

Для вставки коду використовується стандартний Markdown-синтаксис із вказанням
мови (наприклад, ` ```typescript `). Номери рядків НЕ пишіть у самому коді
вручну — вони заважають копіювати код і збиваються після правок. Натомість
один раз після налаштування документа додайте правило, яке нумерує рядки
автоматично (блоки без мови, як-от дерева каталогів, лишаються без номерів):

```typst
#show raw.where(block: true): it => {
  if it.lang == none { return it }
  show raw.line: line => {
    box(width: 1.5em, align(right, str(line.number)))
    h(0.75em)
    line.body
  }
  it
}
```

**Приклад коду в додатку:**

````typst
= Приклади програмного коду
== Запит до API <api-code-ref>
```typescript
const API_KEY = "SECRET";

const url = new URL("https://example.com/api");
url.search = new URLSearchParams({ key: API_KEY }).toString();
```
````
